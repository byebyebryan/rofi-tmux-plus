# Tmux Plus 0.8.0a1 component boundary release

Tmux Plus now delegates native session discovery, prepared networking, Niri
association and explicit actions to the accepted Tmux Observer SDK. The frontend
owns labels, views, filtering, remembered context, frozen confirmation and user
feedback. Fresh CLI inventory remains fresh; picker reads and watch subscriptions
use prepared state without activating services or collecting tmux/SSH facts.
The seven-command Tmux Session v1 facade and its strict errors/exits remain
compatible. Ordinary Open independently checks current unique window evidence;
ambiguous or stale observations grant no focus or close authority.

are 176–189 ms; first native callbacks finish in 384–391 ms. One owned explicit
refresh clears its notice in 266.22 ms, 26.91 ms after the service terminal ticket.
These are isolated polling/callback observations, not compositor presentation or
two-host latency percentiles. Observer's exact ten-minute ordinary-session profile
passes the unchanged five-percent CPU ceiling at 4.3229%/2.6156% on Snap/Starship,
with memory and warm query deadlines passing. Capacity uses synthetic logical
owners on two physical hosts; physical suspend and native-event collection remain

Publication, CI using the published producer, and scoped managed selection,
recovery, paired rollback and reselection are separate gates. Until those gates
are recorded, the selected managed pair remains Observer 0.1.0a1 / Plus 0.7.0a2.
